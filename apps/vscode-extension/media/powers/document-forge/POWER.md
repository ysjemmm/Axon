# 文档处理（Document Forge）

两类场景都用本能力包：
- **读**：用户给了 Excel / PDF / Word，要你分析、汇总、对账、提取其中内容
- **写**：用户要"做成 Excel""生成 Word""导出 PDF"

⚠️ 二进制文档不能直接 `read_file`（.xlsx/.docx 是 zip 包，PDF 是二进制），
读取必须先看 read-document 技能，按它的做法转成文本再读。

## 覆盖范围
| 格式 | 读 | 写 |
|---|---|---|
| Excel（.xlsx）/ CSV | ✅ | ✅ |
| Word（.docx） | ✅ | ✅ |
| PDF | ✅（扫描件除外，需 OCR） | ✅ |

## 工作流程（生成类）
1. **先问清三件事**（缺一不可，不要自行假设）：
   - 内容从哪来：用户直接给的数据 / 工作区里的某个文件 / 需要你整理归纳
   - 要什么格式：Excel / Word / PDF
   - 放哪里：用户指定路径，或按下方约定
2. 读取对应技能的 SKILL.md（路径在 activate_power 的返回里）拿具体做法与模板 —— excel / word / pdf。
3. 生成。
4. **验证**：确认文件确实存在且大小 > 0；要如实报告，不要假定成功。
5. 回复里给出**绝对路径** + 内容结构简述。

## 工作流程（读取类）
1. 确认文件路径存在
2. 按 read-document 技能把文档转成文本/Markdown 落到**临时目录**
3. 读取转换结果并回答用户的问题
4. 数据量大时在脚本里先算好（求和/分组/差异），只把结果读进来 ——
   不要把几万行原始数据全搬进上下文
5. 抽取失败（扫描件/加密/损坏）如实说明，**绝不根据文件名猜内容**

## 输出位置约定
- 用户给了路径 → 用用户的
- 没给 → 主工作区的 `output/` 目录下（不存在就创建）
- 读取产生的中间产物 → 系统临时目录，不要留在用户工作区
- 始终使用绝对路径

## 纪律
- 只为文档处理而工作，不要顺手改用户的项目源码。
- 缺依赖时先装；装不上要如实说明缺什么，不要伪造"已生成"。
- 路径含空格或中文时要正确加引号。
- 面向非技术用户时，回复里不要出现"脚本""依赖""临时目录"这类实现细节 ——
  他们只关心「读到了什么」和「文件在哪」。
